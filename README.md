# huaxun

把自然语言资产搜索需求转成一条 FOFA 查询语句。

参赛包编号是 `pkg-08e82c8d`，题目在 `readme/题目.txt`，共 100 题。程序按题号把查询填进答案，写出可提交的 `答案.json`。

能转换时，每题只写一条查询。不能转换时，固定写这句，不加解释：

```text
该需求不能直接转换为FOFA搜索语句
```

比赛规则见 [readme/README.md](readme/README.md)。实现取舍和任务拆分见 [readme/方案.md](readme/方案.md)。

## 环境

需要 Go 1.22 或更高版本。项目只用标准库，不用先下载第三方包。

## 生成答案

在仓库根目录执行：

```text
go run ./cmd/nl2fofa -name "你的名字"
```

不传 `-name` 时，选手名称保持模板里的空字符串。参赛包编号始终取自模板，程序不会改它。

常用参数：

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `-name` | 空 | 写入「选手名称」 |
| `-questions` | `readme/题目.txt` | 题目文件 |
| `-template` | `readme/答案模板.txt` | 答案模板，题号和参赛包编号以它为准 |
| `-out` | `答案.json` | 生成的答案文件 |

生成前会检查题号：缺题、重复题号、未知题号或某题查询为空，都会直接失败，不会写出半份文件。

## 测试

```text
go test ./...
```

单测覆盖转义、括号、端口和 IP 校验、自相矛盾、国家与云厂商词表，以及全部 100 题的期望查询。改规则后先跑测试，再重新生成 `答案.json`。

## 程序怎么分层

只分三层。`cmd/nl2fofa` 负责把它们串起来。

```text
题目 JSON
    │
    ▼
answer      读题目和模板，按题号回填
    │
    ▼
convert     自然语言 → 查询表达式
    │
    ▼
fofa        表达式 → 一条 FOFA 字符串；不合法则整题拒绝
```

| 目录 | 职责 |
| --- | --- |
| `cmd/nl2fofa` | 命令行入口 |
| `internal/answer` | 读写 JSON，核对题号和参赛包编号 |
| `internal/convert` | 识别字段、且/或/排除、词表、外来语法 |
| `internal/fofa` | 表达式、引号转义、括号、端口/IP/矛盾校验 |
| `internal/convert/lexicon.go` | 国家、地区、城市、云厂商取值 |

词表放在 `convert` 里，不再单独做一层。运行时不访问网络。Jenkins 字段名和图标哈希已经算好写在代码里。

没有任何规则命中时，整题拒绝，不猜测查询。

## 当前答案里被拒绝的题

`答案.json` 里有 6 题使用固定拒绝句：

| 题号 | 原因 |
| --- | --- |
| M091 | 端口 1000000 不在 1 到 65535 |
| M092 | `1.2.3.4.5` 不是 IP，也不是网段 |
| M093 | 国家代码不能既等于 US 又不等于 US |
| M094 | 「最安全」没有对应字段 |
| M095 | 容器内存使用率不是资产搜索条件 |
| M098 | 没有取到仿冒页面，不能把域名本身当成仿冒特征 |

## 如果某题没命中

地区和云厂商的写法集中在 `internal/convert/lexicon.go`。例如巴伐利亚是 `Bayern`，München 是 `Munich`，亚马逊云是 `Amazon`，华为云是 `HuaWeiCloud`。评分反馈字段值不对时，先改这张表，再跑测试并重新生成答案。
